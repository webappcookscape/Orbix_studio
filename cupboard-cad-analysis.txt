1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Cupboard CAD is an advanced, zero-install, browser-native 3D CAD/CAM (Computer-
Aided Design & Manufacturing) web application tailored specifically for interior
designers, modular furniture factories, and cabinet fabrication enterprises.

Unlike generic 3D cabinet visualization tools, Cupboard CAD operates as a full
production-readiness bridge. It transforms 3D parametric concepts directly into
factory-floor outputs aligned with standard Indian job-work manufacturing workflows:
  - Process sheets with exact square-footage (SFT) and edge-banding running feet.
  - 2D guillotine sheet nesting on standard 2440 x 1220 mm (8 x 4 ft) boards.
  - System 32 CNC drilling schedules (hinge cups, shelf pins, drawer runners).
  - Dimensioned 2D CAD elevations and DXF (AutoCAD R12) exports for CNC routers.
  - Ingestion of legacy factory PDF process sheets with automatic 3D rebuilding.
  - Transparent costing and material savings reports comparing ordered boards
    against nested board counts (avoiding arbitrary 20-30% wastage markups).

The application is completely standalone, running 100% client-side with zero
backend server dependencies, zero telemetry, and complete data privacy.

4. CORE ALGORITHMS & MATHEMATICAL FORMULAS
--------------------------------------------------------------------------------
4.1 Square Footage (SFT) Calculation
  Modular furniture manufacturing in India measures panels in square feet while
  drawing dimensions in millimeters:
      Area (SFT) = (Height_mm * Width_mm * Qty) / 92903.04
  (Where 92903.04 mm^2 = 1 square foot).

4.2 Edge Banding Rules & Visual Realism
  Edge banding codes determine which edges receive PVC tape:
  - '4S': All 4 sides banded.
  - '2L': Both long edges banded (standard for carcass gables and shelves).
  - '1L': One long edge banded (e.g., exposed front edge of internal shelves).
  - '1L1S': One long + one short edge banded.
  - '—': Raw unbanded core.
  The 3D renderer dynamically builds multi-material geometries: edges marked with
  banding receive the PVC tape color/texture, while unbanded edges explicitly
  render raw substrate particleboard/MDF core textures.

4.3 System 32 CNC Drilling Specification
  - Hinge Cups: 35 mm diameter bore at 22.5 mm margin from the door edge,
    positioned 100 mm from top and bottom edges.
  - Shelf Pins: 5 mm diameter holes spaced on a standard 32 mm vertical pitch,
    set 37 mm inset from front and back carcass edges.
  - Drawer Slide Fixings: 5 mm diameter holes at 37 mm inset from front edge.
  All hole coordinates are exported directly to the `DRILL` layer in DXF exports.

4.4 2D Guillotine Bin-Packing Nesting Algorithm
  The nesting module executes a 2D guillotine cut optimization:
  - Substrate: 2440 mm x 1220 mm (standard 8 x 4 ft sheet).
  - Kerf Allowance: Saw blade width deducted per cut (default 4 mm).
  - Grain Locking: Woodgrain laminates are strictly locked to sheet orientation
    (length parallel to board length). Solid colors and gloss laminates can rotate
    90 degrees to minimize waste.
  - Placement Heuristic: Implements Best-Area-Fit (BAF) and Best-Short-Side-Fit (BSSF).
  - Offcut Maximization: After each rectangle placement, the leftover space is
    split along its shorter axis, keeping remaining offcut sections in large,
    usable continuous rectangles rather than fragmented strips.

4.5 CAD Drafting & DXF Generation
  Direct procedural generation of AutoCAD DXF R12 ASCII file format:
  - Formats HEADER, TABLES, BLOCKS, and ENTITIES sections without external libraries.
  - Separates cut geometry from machining operations using layer standards:
      * Layer 0 / OUTLINE: Panel perimeter geometry.
      * Layer DRILL: Centerpoints and diameter entities for CNC drill heads.
      * Layer DIMS: Dimension annotation lines and text.

4.6 Tolerant PDF/CSV Reverse-Engineering Parser
  - Ingests scanned or exported process sheet PDFs using PDF.js text stream tokens.
  - Groups textual tokens by Y-coordinate clustering to reconstruct tabular rows.
  - Regex heuristics identify numeric columns (Height, Width, Qty, SFT) and
    material codes (e.g., "MDF 1135", "SF 3410").
  - Maps parsed parts to 3D unit structures (shutters, gables, shelves, lofts),
    allowing a fabricator to verify old cutting lists visually before cutting.

6. DEVELOPER HOOKS & AUTOMATION API (`window.__cc`)
--------------------------------------------------------------------------------
The application exposes a developer namespace on the browser window object:
  - `__cc.audit()`: Headless automated verification script that iterates through
    every catalogue preset and asserts that no door renders with geometric gaps
    or missing panel assignments.
  - `__cc.gl.snapshot(width, height)`: Renders the active 3D scene to an offscreen
    buffer and returns a high-resolution JPEG Data URL.
  - `__cc.setExplode(ratio)`: Animates exploded assembly views separating panels
    outward along their normal vectors for technical manuals.
  - `__cc.setDoors(openRatio)`: Programmatically opens/closes all doors and drawers.
  - `__cc.tour()` / `__cc.spin()`: Starts automated camera orbit presentations.
  - `postMessage` Handler: Enables parent web applications or iframes to control
    the CAD studio remotely (room building, laminate switching, view mode changes).

8. SECURITY, PERFORMANCE & RELIABILITY EVALUATION
--------------------------------------------------------------------------------
8.1 Security
  - Zero Data Exfiltration: Designs, client names, orders, and rates never leave
    the client browser.
  - Zero Injection Vulnerabilities: Parsing routines use strict numeric typing
    (`parseFloat`, `Math.round`) and DOM text nodes/properties rather than unsafe
    `eval()` or unsanitized `innerHTML` injection.
  - Safe for Enterprise & Air-Gapped Networks: Can be deployed in air-gapped
    factory environments without external internet connectivity if Three.js
    and fonts are served locally.

8.2 Performance
  - Load Time: Near-instantaneous (<200 ms) because the initial document is purely
    static HTML and CSS with zero heavy image payloads.
  - Rendering Framerate: Steady 60 FPS WebGL rendering via optimized procedural
    geometry sharing and shared materials cache (`matCache`).
  - Nesting Execution: Guillotine bin-packing computes in under 50 milliseconds
    for standard multi-wardrobe jobs (40-100 panels).

8.3 Architectural Trade-Offs
  - Monolithic `app.js`: Having all application logic in a single 4,600-line file
    keeps deployment and distribution extraordinarily simple (no npm/vite/bundler),
    but makes multi-developer collaboration more challenging without code splitting.
  - Single Project Memory: Application stores one active project in `localStorage`.
    Multi-project file saving/loading (e.g., export/import JSON project archives)
    would be a high-value future addition.
